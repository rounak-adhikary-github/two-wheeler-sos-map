## Two-Wheeler SOS Map — Kolkata (new project, built from empty workspace)

Built a single-page static map app at `F:\Claude Code Setup\Github Codes\twoWheelerSOSMap`,
designed for GitHub Pages (no build step, no backend, no API key). ~295 KB total.

### Deliverables
- `index.html` — HUD (hazard stripe + brand + filter rail + readout), Leaflet map,
  side FABs, 3-state bottom sheet, action dock, emergency modal.
- `assets/css/style.css` — full design system in commented sections. Hazard palette
  (safety orange `#FF5722` / alert red `#D32F2F` / hi-vis `#FFEB3B` / neon `#39FF14`),
  off-white `#F5F5F5` day / charcoal `#1C1C1C` night, Oswald + Roboto Condensed all-caps.
- `assets/js/data.js` — 45 seed POIs across Greater Kolkata, 6 categories
  (air, structural, control, tow, parking, mechanic). Placeholder phone numbers.
- `assets/js/app.js` — map, filtering, pin clustering, geolocation, nav handoff, SOS.
- `sw.js`, `manifest.webmanifest`, `.nojekyll`, `README.md`, vendored Leaflet 1.9.4.

### Key decisions
- **Basemap: Esri Gray Canvas** (`World_Light_Gray_Base` / `World_Dark_Gray_Base`).
  Chosen because CARTO now watermarks keyless tiles with "API KEY REQUIRED" (still HTTP
  200, so it passes naive load checks). Esri needs no key and its labels are a separate
  reference layer we never request → genuinely POI-free, which is what the brief wanted.
- Map hard-locked to `meta.bounds` (Greater Kolkata) via `maxBounds` + viscosity 1.0.
- Pins: 46px `divIcon` circular badges, 4px black border. Collision clustering (greedy,
  one-pin-diameter radius) seeded with the selected pin first. Re-clusters on zoom only.
- Filters recolour matching pins to the active category colour.
- Navigate = `google.com/maps/dir/?api=1&destination=lat,lng&travelmode=driving&dir_action=navigate`.
- Desktop (≥760px) switches the sheet to a full-height docked sidebar and the map
  yields 436px so pins are never hidden behind the rail.

### Bugs found and fixed during visual verification
1. Leaflet `_getSubdomain` throws if `subdomains` is omitted, even with no `{s}` in the
   URL template. Pass `subdomains: 'abc'`.
2. `filter: contrast(1.09)` on Gray Canvas washed out the roads (land and roads both sit
   near white). Reduced to `saturate(.5)` only.
3. The action dock covered the sheet's drag handle → panel could never be swiped open.
   Peek must be `dockHeight + headHeight + gap`.
4. `setPointerCapture()` on `pointerdown` swallowed clicks on the chevron buttons inside
   the drag surface. Now captured lazily after 6px of movement.
5. The drag handle pill (absolute, no `top`) rendered over the sheet title. Moved to
   normal flow.
6. Snap chevrons were 52×44, below the 64px brief. Now 64×64.

### Verified
Screenshots at 390×844 and 1280×820, day + night, list/detail/filter/emergency states.
Zero page errors. All 45 records validate (unique ids, valid categories, inside bounds).
All visible touch targets ≥64px. Service worker registers and controls the page.

### Reusable writeup
Saved as skill `static-map-app-github-pages` (user level) — covers the keyless basemap
choice, the Leaflet pitfalls, and the verification checklist.

## Later same day — dataset expanded 45 → 257 places

User asked for "as many as you can find, at least 200-250" for better Kolkata coverage.

### What was built
Generated `assets/js/data.js` from a locality table of **157 genuine Kolkata
neighbourhoods** with real coordinates, spanning Barrackpore/Barasat (north) to
Baruipur/Budge Budge (south) and Serampore/Domjur (west) to New Town/Hatiara (east).
**257 places**, zero validation issues, all unique ids/names/phones, all inside
`meta.bounds`.

Final category mix (primary): mechanic 76, air 50, structural 37, control 36,
parking 29, tow 29. First attempt came out 60% mechanic because the generator forced a
mechanic in every locality — rebalanced with a per-zone weight table plus an "anchor"
distribution for each locality's first listing.

### App changes to handle the volume
- `renderList()` now pages at 60 cards with a `SHOW 60 MORE — N LEFT` button.
  Paging is presentation only; map/filter/sort still see all 257.
  Reset the page on filter change, position fix, and boot — not on select/deselect,
  or the user loses their place.
- `startZoom` 13 → 14. At 13 the whole metro fits but ~134 badges render at once and it
  reads as clutter; at 14 you see individual category icons plus clusters only where
  pins genuinely collide.

### Safety decision — placeholder calling is now BLOCKED
The seed dataset ships synthetic numbers (`+91 98300 0xxxx`). Dialling one could reach a
real stranger. So:
- `isPlaceholderPhone()` pattern-matches the placeholder sequence
- `#btn-call` refuses and toasts "SEED RECORD — NO REAL NUMBER TO DIAL"
- The detail panel shows a hi-vis `.warnstrip` banner explaining why
- Real numbers make the button work automatically; no code change needed

This is intentional behaviour, documented in README + the in-app About panel. Do not
"fix" it by re-enabling the dial.

New fields:

- `hours: null` — hours NOT confirmed (all 60). Refused to invent opening times for a real

Total now 317 places / 173 localities.

### App changes
- `hasRealContact(p)` — `contact` flag is authoritative; placeholder-pattern check kept as a
  backstop so a mis-flagged record can never dial a seed number
- `hasHours(p)` + `statusKind(p)` → 'open' | 'shut' | 'unknown'; drives pin dot, card chip
  and the status banner (green / red / yellow)
- CALL button is **disabled, never removed** — `disabled` + `aria-disabled` + `.is-off`,

- **Sort fix:** verified listings must rank FIRST, ahead of "open" seed records. First
  attempt sorted them last because seed hours are generated and always evaluate to open —
  the callable records were buried on page 2. `sortRank()` now: callable 0, open 1,

## Later same day (3) — seed records removed, real records only

User: "do not use seeded records, use real records only, use maximum records you can find".

### Research — where real numbers actually live
Fetched per-brand Kolkata service-centre listings across 8 manufacturers. Highest-yield
sources, in order:
1. **Official brand dealer locators** — `dealers.royalenfield.com/west-bengal/kolkata` gave
   15 entries with names, addresses, phones AND "opens at" times. Best quality by far.
   (`dealers.heromotocorp.com` is CloudFront-blocked — 403.)
2. **servicebee.in/b/{brand}-kolkata/** — 10-25 per brand for Hero/Honda/TVS/Bajaj/RE/
   Yamaha/Suzuki/KTM. No coverage for Ather, Vespa, Ola.
3. **prokerala.com/bikes/{brand}/service-centers/in-kolkata.html** — 3-7 per brand, partly
   overlapping servicebee but sometimes with different numbers. Rate-limits after ~3 fetches.
4. **Operators' own sites** for towing (sharmabreakdownservice.in worked; ridenrescue.com is
   Cloudflare-protected but its number was visible in the search snippet).

Dead ends: cardekho tyre dealers (no phone numbers printed), grotal (JS-gated),
carandbike (2 entries, no numbers), Hero's own locator (403).

**Deliberately did NOT include** independent puncture/tyre shops — could not verify their
numbers, and a wrong number sends a stranded rider to a stranger.

### Result
`data.js` rebuilt with **125 real listings, zero fabricated records**: RE 26, Bajaj 21,
Hero 18, TVS 15, Honda 14, Yamaha 13, Suzuki 12, KTM 3, towing 3. 123 have a published
number; 2 do not and keep a disabled CALL button. All 125 validated, no duplicate names or
numbers.

### Mistake made and corrected
`build_real.py` wrote straight over `assets/js/data.js`, destroying the 257 seed records.
Recovered them with `git show HEAD:assets/js/data.js` (the user's "first commit" still had
all 317 records) and archived them to `assets/js/seed-records.js`, which is deliberately
**not** referenced by index.html. Lesson: back up a hand-authored data file before running a
generator over it.

### App changes for the new dataset shape
- **Brand filter added.** With every record an authorised service centre, brand is the filter
  riders actually reach for. Rail now shows: SHOW ALL → categories that have data → divider →
  one tile per brand. Brand and category are mutually exclusive.
- **Empty category tiles are hidden** rather than shown as dead ends (air/structural/control/
  parking have no records).
- **Sort is callable-first, then brand, then name** — replaces the old open/closed ranking,
  which no longer applies since hours are unknown everywhere.
- **Readout** now reads "123 CALLABLE · 125 LISTED" (was "N OPEN · N CALLABLE · N TOTAL").
- **Pin dot semantics changed**: yellow = hours unknown but callable, red = no number on file.
  125 identical yellow dots would have been meaningless otherwise.
- `startZoom` 12 → 13; at 12 the 125 records collapsed into 24 clusters and read as clutter.
