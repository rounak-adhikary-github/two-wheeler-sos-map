## Later same day — Google Maps IS fetchable. 137 → 170 listings

The user pushed back: *"aren't you able to add more local spots from google maps?"* I had
previously told them Maps place pages weren't fetchable. **I was wrong.** Worth re-testing an
assumption before repeating it.

### The finding

`https://www.google.com/maps/search/<query>` — plain URL, **no query parameters** — returns a
fully readable server-rendered result list via WebFetch. Each result gives:

- business name
- category (Motorcycle repair shop / Tyre shop / Towing service / Battery store …)
- street address
- phone number
- **opening hours** ("Open 24 hours", "Open · Closes 7 PM")
- **exact coordinates** — in the place URL as `!3d<lat>!4d<lng>`

Caveats:
- **Adding `?hl=en` triggers a Google cookie-consent interstitial** and you get nothing. The
  bare URL works; the response language varies (Lao, Spanish, German, Arabic, Japanese…) but
  names, addresses, phones and coordinates are language-independent. Only the "Open/Closes"
  words need translating — the times come through numerically in the Japanese locale.
- **Roughly half the requests still hit the consent wall.** Just retry, ideally with a
  reworded query. It is intermittent, not a hard block.

Queries that paid off: `bike repair shop kolkata`, `bike repair kolkata`,
`tyre puncture shop kolkata`, `two wheeler towing service kolkata`,
`two wheeler spare parts kolkata`, `bike battery shop kolkata`, `bike service centre kolkata`.

### Added 33 records

12 more independent workshops, 7 tyre/puncture shops, 6 towing operators, 3 spare-parts
shops, 5 battery dealers (Exide/Amaron). Two new categories: **`battery`** (new colour
`#FF2D95`) and `air` relabelled to **TYRE / AIR / PUNCTURE**.

### Honest hours handling

Maps reports "Open · Closes 7 PM" — a closing time but **not an opening time**, and only
true at capture time. A closing time alone cannot tell you whether a place is open now. So:

- `hours: { o: 0, c: 24 }` **only** where Maps says "Open 24 hours" — complete and accurate.
  13 records. They show a green dot and OPEN 24 HOURS.
- Everything else keeps `hours: null` → yellow dot, `CALL AHEAD`. The closing time goes into
  the note as a listing fact ("Listed open till 7 PM"), never as a live claim.

### Final

**170 listings, 169 callable, 92 localities.** Sources: manufacturer directories 122, Google
Maps 33, public business directories 11, operators' own sites 4.

### ToS caveat (documented in the README)

Google's terms restrict scraping and bulk redistribution of Maps content. Low-risk for a
personal/community project; needs licensing or re-collection before running at scale. This is
stated in the README so the user can make that call knowingly.

## Later same day — fixed: no way out of a selected place

User report: *"when I select a spot, it's really tough to get back to the map screen … if I
want to unselect the selected option and view other options, or view just the map."*

### The actual bug

Not a gesture problem — a **layout** problem. `select()` snaps the sheet to `peek`, which
shows only the sheet *head*. The `BACK TO LIST` button lives at the top of the scrolled
`view-detail` content, so at peek it is **off-screen**. The only visible controls were the two
snap chevrons and the dock. There was genuinely no way out except swiping the sheet up first
and then scrolling to find the button.

Lesson: when a panel only ever shows its header, every escape route must live *in that header*.

### Fix — four exits

1. **Red ✕ button** (`#sheet-close`) in the sheet bar, shown only while a place is selected.
   64×64, `--alert` red, placed **last** in the bar so it is nearest a right thumb. Its click
   handler calls `stopPropagation` or the head's own click handler would also cycle the snap.
2. **Tap the map to deselect** — `map.on('click', …)`. Leaflet does not fire `click` after a
   drag so panning is safe.
3. **`L.DomEvent.stopPropagation(e)` on marker and cluster clicks.** Without it, tapping a pin
   selected it and the bubbled map click deselected it in the same gesture — the selection
   would have flickered on and off.
4. `BACK TO LIST` and Escape already existed and still work.

Also: `#snap-down` is hidden while a place is selected. Three 64px buttons plus a title is too
much for a 320px screen; the head-tap cycle and dragging still collapse the sheet.

### Considered and rejected

A fourth "minimised" snap state to show more map. It does not work with this architecture: the
sheet is `bottom: 0` with `translateY`, so the visible slice is always the sheet's **top** — at
44px you would see the stripe, the grip and the top third of the buttons, i.e. half-cut
controls. Minimum useful height is the head height, which is already `peek`. Not worth it.

### Verified

390×844 and 320×568. ✕ visible at 64×64, right edge 378, clear of the dock. All four exits
return to the list with dock hidden, header un-collapsed, `snap-down` restored. Tapping a pin
keeps it selected. 170 places, 20 tiles, zero page errors.

## Later same day — the filter rail was unscrollable on desktop

User screenshot: the rail cut off at `BAJAJ` / `EN…` with the rest unreachable.

### Cause — two things at once

1. `scrollbar-width: none` + `::-webkit-scrollbar { display: none }` — **no affordance at all**
   that more tiles existed.
2. **A mouse wheel does not scroll horizontally by default.** So on desktop there was literally
   no gesture that reached the tiles past the right edge. Mobile was fine (touch swipe), which
   is why this shipped.

### Fix

- Slim **visible scrollbar** (9px, themed) on the rail.
- `wheel` handler translating `deltaY` into `rail.scrollLeft`. It **only calls
  `preventDefault` while the rail can actually move**, so the page still scrolls once you hit
  either end. Guarded with `{ passive: false }`.
- **Edge fades** via `.railwrap::before/::after`, toggled by `syncRailFade()` on scroll,
  resize and after `renderRail()`. The fade colour is a per-theme `--surface-fade` variable —
  plain `transparent` fades through *black* and produces a grey band.
- `scroll-padding-left/right: 12px`. Without it `scroll-snap` aligns the first tile to the
  padding edge, leaving `scrollLeft: 12` at rest, which made the **left fade show on load**.

### Separate bug found while verifying — duplicate tile labels

`brand` was carrying shop *types* (`TYRE`, `SPARES`, `BATTERY`, `TOWING`) as well as
manufacturers, so the rail rendered a **`BATTERY` category tile and a `BATTERY` brand tile**
side by side, filtering different things. Removed `brand` from 25 records; it now means
manufacturer only, plus the `LOCAL SHOP` pseudo-brand (no equivalent category).

Brand tiles 13 → 9. Rail total 20 → 16 tiles. Documented in the README so it is not
reintroduced.

### Verified

1280×820 and 390×844. Wheel scrolls (12 → 366). At the end `is-less` true / `is-more` false and
the last tile (`LOCAL`) is fully on screen. At rest `scrollLeft` is 0 with no left fade.
16 tiles, zero page errors.
